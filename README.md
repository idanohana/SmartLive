# SmartLive

ממשק ווב בעברית לצפייה בערוצי ה‑IPTV שלך, ולצידו סקשן סרטים וסדרות.

```bash
npm install
npm start
```

ואז לפתוח <http://localhost:4321>.

## מה יש כאן

**שידור חי** — 108 הערוצים מהמנוי, עם לוגו, שם בעברית, תגיות HD/4K, לוח שידורים
(מה עכשיו + מה הלאה) ישירות מהספק, חיפוש, קטגוריות אוטומטיות, מועדפים
ונצפו‑לאחרונה. הנגן בנוי על `mpegts.js` עם זאפינג בחיצים, מסך מלא, PiP וחזרה
לשידור החי.

**סרטים וסדרות** — חיפוש של כל סרט או סדרה (גם לפי מזהה IMDb), מדפים מוכנים,
רשימה אישית והמשך צפייה. לסדרות יש בורר עונות ורשימת פרקים עם תמונות, תאריכי
שידור ודירוגים, ומעבר לפרק הבא/הקודם.

**גרסת טלוויזיה** — ממשק נפרד ב‑`/tv` שמנווטים בו בשלט, ואפליקציית Android TV
שעוטפת אותו. פרטים ב[גרסת טלוויזיה (APK)](#גרסת-טלוויזיה-apk).

## איך זה עובד

```
server/
  index.js      Express: API, פרוקסי שידור, פרוקסי לוגואים, קבצים סטטיים
  xtream.js     לקוח ל‑player_api.php של הספק (ערוצים, מנוי, EPG) + cache
  catalog.js    ניקוי שמות ערוצים, שמות בעברית, תגיות איכות, שיוך לקטגוריה
  vod.js        סרטים וסדרות: IMDb suggestions + TVmaze + בניית קישור הנגן
  vod-shelves.json   המדפים בעמוד הראשי (רשימות של מזהי IMDb — אפשר לערוך)
public/
  index.html, css/, js/app.js (שידור חי), js/vod.js (סרטים וסדרות)
```

**למה צריך שרת ולא רק דף HTML:** הערוצים מגיעים כ‑MPEG‑TS גולמי מכתובת שאין בה
כותרי CORS, הדפדפן לא יכול לפנות אליה ישירות, והסיסמה של המנוי לא אמורה לשבת
בקוד שרץ בדפדפן. השרת מחזיק את הפרטים ומגיש לדפדפן `/stream/<id>` נקי.

**חיבור אחד בכל רגע:** המנוי מוגבל לחיבור יחיד, ולכן השרת סוגר את השידור הקודם
כשמבקשים חדש. אפשר לשנות עם `MAX_STREAMS` ב‑`.env` אם משדרגים מנוי.

**הספק מנתק כל כמה שניות** — זו התנהגות רגילה שלו, ונגנים אמורים להתחבר מחדש.
השרת עושה את זה בשקט ומגיש לדפדפן זרם אחד רציף.

## הגדרות

`.env` (לא נכנס ל‑git):

```
IPTV_HOST=http://line.ottcst.com:80      # נזרע לחשבון המנהל הראשון
IPTV_USERNAME=...
IPTV_PASSWORD=...

SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SERVICE_KEY=sb_secret_...       # צד שרת בלבד
SUPABASE_PUBLISHABLE_KEY=sb_publishable_...

PORT=4321
MAX_STREAMS=1
ADMIN_USERNAME=admin
ADMIN_PASSWORD=...                       # לחשבון הראשון בלבד
```

## חשבונות וכניסה

הכניסה לאתר דורשת שם משתמש וסיסמה. המשתמשים נשמרים ב‑Supabase, וכל משתמש מקושר
לפלייליסט לייב משלו — כך שכל אחד רואה את הערוצים של המנוי שלו.

**התקנה חד‑פעמית:** פתח <http://localhost:4321/setup>, העתק את ה‑SQL והרץ אותו ב‑SQL
Editor של Supabase. אחרי זה השרת יוצר אוטומטית חשבון מנהל ראשון (ברירת מחדל:
`admin` / מה שרשום ב‑ADMIN_PASSWORD) ומקשר אליו את הפלייליסט שב‑`.env`.

**דף הניהול** נמצא ב‑<http://localhost:4321/admin> ומאפשר:

- ליצור משתמש (שם, שם לתצוגה, סיסמה מוגרלת, הרשאת משתמש/מנהל)
- להדביק קישור פלייליסט (`get.php?username=…&password=…`) — השרת מפרק אותו לבד
- **בדוק חיבור** לפני השמירה: מראה אם המנוי תקין, כמה ערוצים יש ומתי הוא נגמר
- להוסיף כמה פלייליסטים לאותו משתמש, להשבית משתמש, לאפס סיסמה או למחוק

### איך האבטחה בנויה

- סיסמאות נשמרות כ‑scrypt hash, אף פעם לא כטקסט.
- העוגייה היא HttpOnly וחתומה ב‑HMAC, בלי שמירת סשנים בצד השרת.
- מפתח ה‑service של Supabase נשאר בשרת בלבד; הדפדפן לא מדבר עם Supabase.
- על הטבלאות מופעל RLS בלי policies — כך שהמפתח הציבורי לא יכול לקרוא כלום.
- מגבלת החיבורים נספרת לכל פלייליסט בנפרד, כך שמשתמש אחד לא מנתק אחר.

### הסתרת ספק השידור החי מהלקוחות

לקוח שפותח F12 לא אמור ללמוד מאיפה מגיעים הערוצים. כל מה שהדפדפן שלו מבקש
מגיע מהדומיין שלך בלבד:

| מה שהיה נחשף | איך זה נסגר |
| --- | --- |
| `/logo?url=http://logo.<ספק>/X.png` על כל ערוץ | `/logo/<id>` — השרת מתרגם את המזהה לכתובת האמיתית |
| `logo` עם כתובת הספק בתוך `/api/channels` | מוחלף לנתיב אטום לפני השליחה |
| `server: "<הספק>"` ב‑`/api/account` | מוסתר; הלקוח רואה את **שם החבילה** שנתת לו |
| שם המשתמש של הקו ב‑`/api/account` | `null` ללקוח, גלוי רק למנהל |
| **הקו המלא (host + שם + סיסמה) ב‑`/api/auth/me`** | מוסר לגמרי — מגיעים רק `id` ו‑`name` |
| הודעות שגיאה עם כתובת הספק | מנוקות ללקוח, המלא נשאר ב‑log של השרת |

השידור עצמו עובר דרך `/stream/<id>` אצלך, כך שגם בזמן צפייה לא נראית שום
כתובת חיצונית. בדף הניהול המנהל עדיין רואה הכול — שם צריך את הפרטים.

**מה שנשאר חשוף:** הנגן של סרטים וסדרות הוא `iframe` לספק חיצוני, והבקשות שלו
נראות ב‑Network. אי אפשר להסתיר אותן בלי להעביר את כל הווידאו דרך השרת שלך
ולעקוף את מנגנון ההגנה של אותו ספק. אם הפרטיות שם קריטית, הדרך הנקייה היא ספק
VOD עם API מסחרי שמתיר proxy בצד שרת.

## גרסת טלוויזיה (APK)

`http://<השרת>:4321/tv` הוא ממשק נפרד שנבנה למסך גדול ולשלט: ניווט ב‑D‑pad,
רצועות אופקיות בסגנון נטפליקס, hero גדול, וטקסט בגדלים שנקראים מהספה. הוא עובד
בכל דפדפן של טלוויזיה, וזה גם מה שה‑APK מציג.

**איך זה מנווט**

| כפתור בשלט | מה קורה |
| --- | --- |
| חיצים | מעבר בין פריטים — הפוקוס עובר לפריט הקרוב ביותר בכיוון שלחצת |
| OK | הפעלה · בתוך שידור חי פותח את רשימת הערוצים · בסדרה פותח את בחירת הפרקים |
| ▲▼ בזמן צפייה | החלפת ערוץ (זאפינג) |
| חזרה (BACK) | סוגר שכבה אחת: נגן ← רשימה ← תפריט ← יציאה מהאפליקציה |

### בניית ה‑APK

הפרויקט נמצא ב‑`android/` — אפליקציית WebView קטנה (Java, בלי תלויות) שעוטפת את
`/tv`, עם רישום ל‑**Leanback launcher** כדי שתופיע במסך הבית של Android TV.

```bash
cd android
gradle assembleRelease      # או: פתח את התיקייה ב-Android Studio
```

ה‑APK נוצר ב‑`android/app/build/outputs/apk/release/`. הוא חתום בחתימת debug,
כך שאפשר להתקין אותו בצד (sideload) בלי שום הגדרה נוספת. אם אין SDK מקומי, יש
workflow מוכן ב‑`.github/workflows/android.yml` שבונה אותו ב‑GitHub ומצרף את
הקובץ לריצה.

### התקנה על הטלוויזיה

1. העבר את ה‑APK לטלוויזיה (Downloader, USB, או `adb install`).
2. פתח את SmartLive — במסך הראשון הזן את כתובת השרת, למשל `192.168.1.10:4321`.
   **השרת מדפיס בהפעלה את הכתובות שעובדות מהרשת**, אז פשוט העתק משם.
3. הכתובת נשמרת; בפעם הבאה האפליקציה נכנסת ישר.

**שים לב:** המחשב שמריץ את השרת צריך להיות דולק ובאותה רשת, ו‑Windows Firewall
צריך לאשר את הפורט 4321. אם האפליקציה לא מצליחה להתחבר היא חוזרת למסך הכתובת.

## על הפרסומות בסרטים ובסדרות

הנגן של vidsrc מגיע עם פרסומות קופצות, והוא **מסרב לרוץ בתוך `<iframe sandbox>`** —
יש לו סקריפט שמזהה את זה ומעיף את המסגרת לעמוד שגיאה. לכן החסימה כאן עובדת
בשלוש דרכים אחרות:

1. **מגן לחיצה** — הלחיצה הראשונה על הנגן נבלעת בשכבה שלנו. חלונות קופצים צריכים
   "מחווה" של המשתמש, והלחיצה הראשונה היא בדיוק זו שהם מחכים לה.
2. **מנעול ניווט** — כל עוד הנגן פתוח, ניסיון להעיף את הדף לאתר אחר יעצור
   ויבקש אישור.
3. **זיהוי** — אם בכל זאת נפתח חלון, המונה בראש הנגן מתעדכן ומופיעה הודעה.

לחסימה מלאה (כולל הבאנרים בתוך הנגן עצמו) כדאי להתקין **uBlock Origin** בדפדפן —
זה הדבר היחיד שחוסם גם את מה שרץ בתוך המסגרת של ספק הנגן.
